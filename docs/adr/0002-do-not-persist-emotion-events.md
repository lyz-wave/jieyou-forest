# 未保存的表达不落库，本地存储明文且不加密

PRD §9.2 与 §9.3 要求「未保存的输入仅保留当前会话状态」「未授权保存时不持久化原始输入」，F04 验收更写明「只有用户自愿保存记录才新增年轮」。架构 v1 的 EMOTION_EVENT 表则每次情绪表达都写一行，与之直接冲突。同时，交付形态从浏览器改为 Mac 应用后，数据从浏览器存储变成应用数据目录下的明文 SQLite 文件。

决定：Session 行只在用户按下保存之后才写入，未保存的会话只存在于主进程内存、退出即消失；不加密，改用四项配套换取诚实——目录权限 0700、可见的清空入口且删除后可校验、演示模式默认只跑合成数据、对外表述明确说「明文存储在本机，不加密，能访问这台电脑文件系统的人就能读到」。

理由：PRD 本来就不承诺加密；加密一个演示用的合成数据集是没有威胁模型的表演，而「敢把弱点说清楚」恰好是这个产品的人设。

## Considered Options

- **SQLCipher 全库加密**：better-sqlite3 要换加密分支并重编译原生模块，48 小时内是纯风险。
- **只加密原文正文字段**（Electron safeStorage，底层走 macOS 钥匙串）：代码量小且精准，但未签名的 .app 访问钥匙串可能在演示现场弹出系统授权框——拿演示稳定性换一个演示数据本就不需要的保护。

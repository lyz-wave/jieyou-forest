# 交付形态定为 Mac .app，放弃手机 Web

PRD v2.0 §9.1 把交付形态定为手机浏览器 Web（Next.js + SVG + 浏览器本地存储，验收 390px 与 1440px），而 48 小时封包架构 v1 画的是双击打开的 Mac 应用。两者不能共存：48 小时里只够做一套。我们选 Mac .app，因为它的确定性是这个方案最值钱的东西——离线可跑、无部署、无网络依赖、现场零外部变数，而双形态在 48 小时内通常两边都不稳。

代价是明确的，已写进架构文档：放弃手机浏览器验收，并承认放弃了「深夜在被窝里打开」这个最真实的使用场景；PRD §12.2 的「两种宽度无横向溢出」改为「窗口最小宽度可读」。

## Consequences

数据层从浏览器存储改为应用数据目录下的 SQLite 文件，威胁模型随之改变（见 ADR-0002）。若赛后要回到 Web，数据层与安全闸门可以整体复用，渲染层需要重写。
